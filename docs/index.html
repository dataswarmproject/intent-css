Say what it is.
Not what it looks like.

Intent is a styling system with a closed vocabulary of semantic roles. Markup declares meaning — card, primary action, related stack — and the theme decides the pixels. One OKLCH hue seeds the palette, relationships derive the spacing, and a design linter audits the result, in light and dark, for humans and AI coding agents alike.

Utility CSS says

<div class="bg-white dark:bg-zinc-900
  rounded-xl shadow p-6 flex
  flex-col gap-3">

Nine visual decisions, re-made at every call site. Consistency is discipline.

Intent says

<div class="card stack-related">

Two decisions of meaning. Dark mode, density, and rebrands become theme swaps.

Semantic classes make design reviewable: typos, duplicate primaries, WCAG contrast — at build time.

Four pillars

Roles, not values

A finite vocabulary of 41 roles. A class is either meaningful or it's an error — nothing in between.

Relationships, not numbers

Spacing is related, separate, or sectioned. One base and one ratio derive every distance.

Modern CSS native

Container queries by default, light-dark() theming, OKLCH color math, cascade layers. No legacy tail.

Built for AI agents

A bounded vocabulary agents can't hallucinate past, check --json to self-correct, and an AGENTS.md contract from intent init.

Feedback, audited

Info — every note color pair is contrast-checked in both schemes.

Success — the default theme ships passing its own audit.

Warning — two primary actions in one card? The linter will tell you.

Danger — inline styles are invisible to the system, so they're flagged.

One hue in, a system out

The entire palette on this page derives from brand: { hue: 264 }. Change one number and surfaces, links, actions, notes, focus rings, and shadows follow — with contrast guarantees intact.

export default {
  brand: { hue: 264, chroma: 0.16 },
}
